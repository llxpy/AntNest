## 0. v2 修订说明

### 0.1 两处事实错误（写进 mockup 的假信息）

| v1 声称 | 实测 | 后果 |
|---|---|---|
| 「内置 **17** · 蚁后现在能做什么」 | `TOOL_SPECS` 有 17 条，但 `queen_visible` 是 **14**，`exposed_specs()` 是 **12**（2 条 `worker_only`：`run_cli`/`run_python`；1 条 `panic_only`：`leave_memory_hints`；2 条 MCP 门控） | 标题直接撒谎。且这个数字还会随 MCP 开关变 |
| 「改自身源码是 **L5** 且永远要问我」 | `TOOL_SPECS` **只用到 L0–L3**。L4(`SYSTEM`)/L5(`SELF_MOD`) 在 `PermLevel` 里存在，但**没有任何工具行是这个等级** | L5 是权限闸门的**参数敏感判定结果**（`explicit_confirm` 优先于等级），不是工具的静态属性。v1 凭空捏造了一行 |

> 这两条尤其要命：AGENTS.md §3 明令「文档与 UI 措辞不得夸大」，
> 而 v1 恰好在**最抢眼的 mockup** 里夸大了。**数字必须由数据源算出，不能手写。**

### 0.2 一个致命实现缺陷

v1 的 `collect_skills()` 若放在模块级自由函数，会**打死整个 GUI**：

```
antnest_toolforge.tools_dir() → _A() → import AntNest (:28-29)
    → antnest_config.py:116-120   无 API Key 时 sys.exit(1)
```

而技能表恰恰是**用户可能在第一次对话之前**就点开的入口。
`antnest_bridge.py:776` 存在的全部意义就是防这个 `SystemExit`。

**修正**：改为 `Bridge.skill_table_payload()`（Bridge 方法，`if not self.ready` 早退），
且新增的读取器 `iter_tool_meta(base_dir)` **接收显式目录**，
不碰 `_A()`，不触发 `import AntNest`。

### 0.3 范围错误（三处该砍的）

1. **砍掉 Skills 分组。** `_skills_modal()`（`prototype_antnest.py:7311`）**已经存在**且
   已接进布局（`:13867`），走 `toggle_skills_modal` 路由。新表再画一遍是
   **同一份数据的第二次渲染、且经由第二条代码路径**。
   砍掉它还顺带消灭了「设计里的 `SKILLS_DIR` 根本不存在」这个死结
   （真实契约是 JS 侧 `SETTINGS["skills_dir"]` → `bridge.list_skills(dir)`，`:220`）。

2. **改用既有的「小面板 + 展开」范式，而不是新模态窗。**
   右栏的惯用法是「极简面板 + `btn-expand` → 模态窗」（`:13584`/`:13685`/`:13713`，
   并被 `tests/test_topbar_model.py` 钉住）。
   **更关键的是**：如果蚁后变强这件事只能靠「用户主动点开才看见」，
   那它等于装饰 —— 而这正是本功能要解决的问题本身（v1 自己的 K4 已承认）。
   所以右栏常驻一个带计数的「蚁后能力」面板，展开看全表。
   顺带修正：v1 说右栏「已有四块」，实际是**五块**。

3. **砍掉三处镀金**：版本号 + 相对时间（`ui_render` 里没有日期格式化约定，
   且蚁后很少升级工具）；两级描述回退（**当前 `.antnest/tools/` 是空的**，
   为不存在的样本设计回退链）；悬停/展开看描述（用户没理由读）。

### 0.4 v1 漏掉的文件与事实

- **`antnest_schemas.py` 被漏了**。只给 `register_tool` 加 Python 参数，
  蚁后仍然看不到这个字段 —— 模型的唯一视图是 `register_tool_schema`
  （`antnest_schemas.py:357-379`）。不改 schema，整个 LLM 侧功能**静默失效**。
- **`register_tool` 覆盖会抹掉 `display_name`**。`antnest_toolforge.py:77-87`
  每次重建 `meta` 并整体覆写，不与旧文件合并。而「蚁后改进自己的工具」
  正是设计里让用户看的故事 —— 那条路径恰恰会丢名字。
- **K1 的技术说法是错的**：Python 没有编译期字段校验，
  `frozen=True` 与此无关。改成 `display: str = ""`（带默认值），
  不重排 17 个构造点，**S1 才是真正的护栏**。
- v1 引用了「理由同 `antnest_diag`」——**`antnest_diag` 模块不存在**，
  它是 `docs/v1.4.1-DESIGN.md:220` 里的未实现计划。拿计划当既有范式引用，
  正是 AGENTS.md H3 要防的漂移。

## 1. 数据源（只有两类）

| 来源 | 存储 | 现有元数据 | 可读名 |
|---|---|---|---|
| **内置能力** | `antnest_registry.TOOL_SPECS` | `name`/`level`/`summary`/`queen_visible` | **新增 `ToolSpec.display`** |
| **自撰工具** | `.antnest/tools/<n>/tool.json` | `name`/`version`/`description`/`category`/`updated_at` | **新增可选 `display_name`** |

**硬约束（AGENTS.md §4）**：可读名必须挂在 `ToolSpec` 上（单一真源），
不得另建 `{name: 中文名}` 映射表 —— 那张表必然与 `TOOL_SPECS` 腐烂。

**自撰工具的可读名回退链只留两级**：

```
tool.json 的 display_name  →  name 原样（pdf_extract → pdf_extract）
```

理由：`.antnest/tools/` **当前是空的**。为不存在的样本设计三级回退，
是拿不到真实样例时的空想。凑齐三个真实样本再加。

## 2. 界面

### 2.1 右栏常驻小面板 + 展开（沿用既有范式）

```
┌ 蚁后能力 ──────────── 能力表 ┐
│ ▤ 能力表 12 · 自撰 0            │   ← 计数常驻：蚁后变强的可见信号
└────────────────────────────────┘
```

计数徽记**常驻**在「当前概览」里。展开后：

```
┌ 能力表 ──────────────────────┐
│ ▾ 内置能力            12 项   │   ← 数字由 exposed_specs() 算出
│   派出工蚁    L2  派工蚁在隔离目录执行命令 │
│   查看文件    L0  只读查看文件内容         │
│   …（其余 10 项）                       │
│   ▸ 工蚁专用             2 项 │   ← run_cli / run_python，蚁后用不了
│ ▾ 自撰工具             0 项   │   ← 空态：「蚁后还没自撰过工具」
│   PDF 文本提取                    │   ← display_name
└─────────────────────────────────┘
```

### 2.2 游戏化的两处落点（有信息量，不是装饰）

1. **权限等级色标** L0–L3 —— 安全相关的真实信息。**只画真实存在的等级**，
   数字由 `TOOL_SPECS` 实际用到的等级算出，附一行图例说明各档含义。
   **不画 L4/L5**：它们没有工具行。
2. **来源分区 + 计数** —— `自撰工具 ×N` 这个 N 就是学习成果的量化，随时间增长。

### 2.3 渲染通道

沿用既有范式（`app.update("#subtasks", _subtasks_html(...))`）：

- `ui_render.render_skill_table(payload) -> str`（**纯函数，可在 Python 测试里验证**）
- `app.update("#skill-table", html)`（`phtmlwin.py:436`）

**不写 JS 拼字符串。** `tests/test_ui_wiring.py:288-298` 明确要求
`app.js` 用 `textContent` 而非 `esc()`；把 HTML 生成留在 Python 侧，
JS 只负责一个计数徽记的 `textContent`。

## 3. 数据流

```
用户点「能力表」
  → pywebview: open_skill_table
  → Bridge.skill_table_payload()          ← Bridge 方法，非模块级函数
       if not self.ready: return {"status": "not_ready"}   ← 防 sys.exit
       base = self.mod.PROJECT_ANT_DIR                       ← 复用已加载的模块
       ├─ 内置：antnest_registry.exposed_specs()  → {name, display, level, summary}
       │         + 单独列出 worker_only 的两条
       └─ 自撰：antnest_toolforge.iter_tool_meta(base)  ← 显式传目录，不碰 _A()
  → ui_render.render_skill_table(payload)   ← 纯函数
  → app.update("#skill-table", html)
```

**三个可测缝隙**（v1 把它们混在一起，导致 S9/S10 只能 mock 被测对象）：

| 层 | 性质 | 覆盖的测试 |
|---|---|---|
| `iter_tool_meta(base_dir)` | 真文件系统 + 真 fail-soft | S10 损坏的 tool.json |
| `build_skill_payload(specs, metas)` | **纯函数** | S5/S6 回退链、S9 空库 |
| `render_skill_table(payload)` | **纯函数** | S7/S8 转义截断、S11 色标 |

`iter_tool_meta` **不读 `tool.py` 源码**——`list_tools()` 为了数字数会
`open(tool.py).read()`（`:118-123`），那是给模型复用的，不该为画一张名字表付出。

## 4. 实施顺序

| 步 | 内容 | 文件 |
|----|------|------|
| 1 | `ToolSpec.display: str = ""` + 12 条可读名（写在 `TOOL_SPECS` 声明处） | `antnest_registry.py` |
| 2 | `register_tool` 加 `display_name` 参数，**并与旧 meta 合并**（不覆盖丢名） | `antnest_toolforge.py` |
| 3 | **schema 同步** —— 否则蚁后看不到这个字段，功能静默失效 | `antnest_schemas.py:357` |
| 4 | `iter_tool_meta(base_dir)`：显式目录、fail-soft、不读源码；`list_tools` 改为基于它 | `antnest_toolforge.py` |
| 5 | `build_skill_payload()` 纯函数（回退链在此） | `antnest_toolforge.py` |

| 7 | `render_skill_table()` 纯函数 + 等级色标 | `ui_render.py` |

| 9 | `tests/test_skill_table.py`（S1–S10） | `tests/` |

> 因此不触及 `pyproject.toml` / `installer/AntNest.iss` / mypy 列表（AGENTS.md H2）。

## 5. 测试

| # | 断言 | 守住什么 |
|---|------|---------|
| S1 | 每个 `ToolSpec` 的 `display` 非空 | 缺名会静默退化成机器名 |
| S2 | `display` **互不相同** | 同名词让用户分不清两行 |
| S3 | `display != name`（**仅内置工具**） | 否则等于没做这件事 |
| S4 | `queen_visible` 的每一条都有 `display` | 工蚁专用工具不参与蚁后展示 |
| S5 | 自撰工具 `display_name` 缺失时回退到 `name`，**结果非空** | 空回退会渲染出空行 |
| S6 | 损坏的 `tool.json` 被跳过而非抛出，**且计数只算好的** | fail-soft，延续 v1.4 事件日志约束 |
| S7 | 渲染对恶意 `display_name` 转义（`ui_render.esc()`） | 名称来自模型输出 = 不可信输入 |
| S8 | 渲染对超长 `display_name` 截断 | 同上 |
| S9 | 空自撰库不崩，且空态文案在场 | 零自撰工具是**常态** |
| S10 | 等级色标只覆盖 `TOOL_SPECS` 实际用到的等级 | **防再次画出 L4/L5 这种不存在的行** |

**可测性诚实说明**：面板开关与布局不在 Python 测试覆盖内
（CI 有 `ubuntu-latest`，且 `load_js()`/`load_css()` 内联进 HTML 无热重载）。
手工验证项：真实点开面板一次。记为遗留 R12。

## 6. 风险

| ID | 风险 | 缓解 |
|----|------|------|
| K1 | `display` 成为第二处需同步的清单 | 挂在 `ToolSpec` 上（默认值 `""`），S1/S2 守住；不另建映射表 |
| K2 | 蚁后写的 `display_name` 乱码/超长/含 HTML | 等同不可信输入：S7/S8 + 采集侧长度上限 |
| K3 | `.antnest/tools/` 被手工改坏 | `iter_tool_meta` 逐项 try/except，S6 |
| K4 | 覆盖更新丢 `display_name` | 第 2 步的合并逻辑 + 回归测试 |
| K5 | 在核心未加载时被调用 → `sys.exit` | `Bridge` 方法 + `self.ready` 早退 + 显式传目录（不碰 `_A()`） |
| K6 | 计数随 MCP 开关变化，用户困惑 | 数字每次现算并在标题注明口径（「蚁后可见」而非「全部」） |

## 7. 不做

- **不做 Skills 分组** —— `_skills_modal()` 已存在且已接线。
- **不做技能树 / 依赖图** —— 工具之间无依赖关系，画出来是假的。
- **不做版本号与相对时间** —— `ui_render` 无日期格式化约定，且蚁后很少升级工具。
- **不做多级名称回退** —— 当前零存量样本，等有三个真实样本再加。
- **不做悬停展开描述** —— 用户没理由读。
- **不做「让用户编辑技能名」** —— 蚁后下次 `register_tool` 会覆盖。
- **不做调用次数统计** —— 需要在 `antnest_events` 加计数器，收益待验证。
